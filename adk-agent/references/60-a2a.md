# 60 A2A — エージェント間連携

> いつ読むか: design で複数エージェントをネットワーク越しに連携させるとき、scaffold で `to_a2a` / `RemoteA2aAgent` を書くとき。
> 出典: 第 7 章、第 9 章原則 8（要約・再構成）

## MCP との違い・使い分け

| 観点 | A2A | MCP |
|---|---|---|
| 目的 | エージェント ⇔ エージェント（双方向） | エージェント → ツール（単方向） |
| 通信先 | 自律的（LLM が応答、非決定的） | 受動的ツールサーバー（決定的） |
| 発見 | Agent Card `/.well-known/agent-card.json` | 設定ファイル |
| 状態 | Task の状態遷移あり | ステートレス |

外部 DB / API は MCP、専門性の異なるエージェントへの委譲は A2A。

**ADK オーケストレーション vs A2A** の軸は **チーム境界**: 同一チーム・Session/State 共有・低レイテンシ → ADK（sub_agents / Workflow、単一デプロイ）。異なるチーム・組織・フレームワーク・独立デプロイ → A2A。実際はデプロイユニット内は ADK、ユニット間は A2A。

## A2A の 5 概念（v1.0 系。2025 年 6 月に Linux Foundation 移管）

- **Agent Card**: `name` / `description` / `url` / `version` / `capabilities`（streaming, push_notifications）/ `skills`（id, name, description, tags, examples）/ `default_input_modes` / `default_output_modes`（以上 REQUIRED）+ `protocol_version` / `preferred_transport` / `additional_interfaces` / `provider` / `security_schemes`。skill の description は「データを登録する」のような抽象記述にせず具体的に、examples 併記
- **Task**: 状態 `SUBMITTED → WORKING → COMPLETED | INPUT_REQUIRED（追加情報）| AUTH_REQUIRED | FAILED | CANCELED | REJECTED`。`contextId` で複数 Task をグループ化
- **Message**: `role`（USER = クライアント側エージェント、AGENT = サーバー）+ `parts`
- **Part**: v1.0 は単一 Part（`text` / `raw` / `url` / `data` の oneof + metadata / filename / mediaType）
- **Artifact**: 処理結果（`artifactId` / `name` / `parts`）

設計原則: Discovery / Task Management / Collaboration（`INPUT_REQUIRED` で質問を返せる）/ Streaming（SSE）/ Opaque Execution（内部実装を公開しない）。

バインディング: JSON-RPC（a2a-sdk 0.3.x 既定）/ gRPC / HTTP+JSON。操作: `SendMessage` / `SendStreamingMessage` / `GetTask` / `ListTasks` / `CancelTask` / `SubscribeToTask` / `CreateTaskPushNotificationConfig`。

## ADK v2.2.0 の実装（a2a-sdk 0.3.x）

依存: `google-adk[a2a]==2.2.0` + `a2a-sdk>=0.3.24,<0.4.0`（1.x 系を入れると `ImportError: cannot import name 'ClientEvent'`）。experimental のため `ADK_SUPPRESS_EXPERIMENTAL_FEATURE_WARNINGS=1` で警告抑制可。

### v1.0 仕様 ↔ 0.3.x 実装の差分

| 項目 | v1.0 仕様 | a2a-sdk 0.3.x |
|---|---|---|
| Agent Card url | `supportedInterfaces[].url` | トップレベル必須 |
| Part | 単一 Part（oneof） | `Part(root=TextPart\|FilePart\|DataPart)` |
| TaskState | `TASK_STATE_INPUT_REQUIRED`（SCREAMING_SNAKE） | `"input-required"`（`TaskState.input_required`） |
| メソッド名 | `SendMessage`（PascalCase） | `message/send` |
| 再購読 | `SubscribeToTask` | `resubscribe` |
| Push 登録 | `CreateTaskPushNotificationConfig` | `set_task_callback` |
| Role | `ROLE_USER` / `ROLE_AGENT` | `Role.user` / `Role.agent` |
| 認証 | `securitySchemes` / `securityRequirements` | `security_schemes` / `security` |

### サーバー（3 ステップ）

1. 通常の `Agent` を定義（ビジネスロジックは A2A 非依存。同じ定義を `adk web` / Agent Engine にも使える）
2. `AgentCard(name, description, url, version, capabilities=AgentCapabilities(streaming=True), default_input_modes=["text"], default_output_modes=["text"], skills=[AgentSkill(...)])`。省略時は自動生成
3. `app = to_a2a(agent, host="0.0.0.0", port=8001, agent_card=card)`（`google.adk.a2a.utils.agent_to_a2a`）→ `uvicorn.run(app, ...)`。`/.well-known/agent-card.json` と `/`（JSON-RPC）が公開される。Cloud Run では `PORT` と `SERVICE_URL` 環境変数で `agent_card.model_copy(update={"url": service_url})`

不足情報の要求は自然文で返さず **`request_input` ツール**（`google.adk.tools`）を使う → Task が `input_required` になる。

### クライアント

- **高レベル（推奨）**: `RemoteA2aAgent(name, description, agent_card=<URL | AgentCard | ファイルパス>)`（`google.adk.agents.remote_a2a_agent`）。単一委譲で完結するなら `sub_agents`、親が途中結果を受けて複数リモートを順に呼ぶなら `AgentTool(agent=remote)` として `tools=`。認証ヘッダ付与は `a2a_request_meta_provider` / `a2a_client_factory`
- **低レベル**: `client = await ClientFactory.connect(url)` → `client.send_message(create_text_message_object(content=...))` は `(Task, UpdateEvent|None)` タプル or `Message` を yield。`input_required` の継続は `task.status.message` の `adk_type == "function_call"` な DataPart を見つけ、`FunctionResponse` を `convert_genai_part_to_a2a_part` で Part 化して `Message(role=Role.user, parts=[...], task_id=task.id, context_id=task.context_id)` で返す（RemoteA2aAgent はこれを内部で処理）

### ストリーミング・再接続・Push

- `capabilities.streaming=True` なら `to_a2a` が SSE 化。イベント 3 種: `TaskStatusUpdateEvent` / `TaskArtifactUpdateEvent` / `Message` を型で分岐
- 切断時は `client.resubscribe(TaskIdParams(id=task_id))` を指数バックオフ（2→4→8 秒、最大 3 回）で再接続し、`get_task` で最新状態を確認
- 長時間タスクは Push Notification（`TaskPushNotificationConfig` → Webhook）。Webhook は Bearer 認証必須
- A2UI（表示）3 パターン: シーケンシャル（チャット）/ 並列統合（Hub-Spoke 結果集約）/ ダッシュボード（エージェント別状態カード）。中間メッセージ送出 API は限定的 → ツール進捗は before_tool_callback でログ

## 協調パターン 3 つ

| 基準 | Hub-Spoke | Pipeline | Peer-to-Peer |
|---|---|---|---|
| 制御の明確さ | 高 | 高 | 低 |
| スケーラビリティ | 中（Hub がボトルネック） | 高 | 高 |
| 耐障害性 | 低（Hub 停止で全停止） | 低（ステージ停止で後続停止） | 高 |
| デバッグ | 容易 | 容易 | 困難 |
| 適用 | 汎用業務自動化 | データ変換 | 分散マイクロサービス |

**実務は Hub-Spoke から始める**。Pipeline は各ステージを独立デプロイし `SequentialAgent` / Workflow で接続（`output_key` で中間結果）。P2P は **循環呼び出し防止が必須**（呼び出し深度制限 / トレース ID で同一エージェント再訪を拒否 / 呼び出し関係を DAG に制約）。

## 認証

選定: 組織間 → OAuth2（Authorization Code）。同一組織でユーザー委任不要 → mTLS 対応インフラあり → mTLS、なければ OAuth2 Client Credentials。単純用途は API Key。

- Agent Card の `security_schemes`（oauth2 clientCredentials + scopes、`mutualTLS`）と `security` で要件宣言。スキル単位でも可
- クライアント: `AuthInterceptor(credential_service=InMemoryContextCredentialStore())` を `ClientFactory.connect(url, interceptors=[...])` に。トークンは `ClientCallContext(state={"sessionId": ...})` で渡す。スキーム名（`bearerAuth` 等）をサーバー側と一致させる。401 でトークン再取得
- サーバー: `to_a2a()` の Starlette アプリに `add_middleware(OAuth2Middleware)`（`/.well-known/` は認証不要、Bearer 検証、スコープ不足は 403）
- mTLS: `ssl.SSLContext` に証明書 + CA を読み `httpx.AsyncClient(verify=ctx)` を `ClientConfig(httpx_client=...)` で渡す。GCP は CAS + Cloud Service Mesh
- 原則: 最小スコープ、トークン有効期限 15 分〜1 時間で自動更新、環境ごとに認証分離（認証なしは開発のみ）、Secret Manager、認証結果を監査ログ

## デプロイ

A2A サーバーごとに独立デプロイ（Cloud Run が汎用、GKE は複雑なネットワーク、Agent Engine は ADK マネージド）。`gcloud builds submit --tag ...` → `gcloud run deploy ... --allow-unauthenticated`（本番は外して認証設計を適用）。`adk web --a2a` / `adk deploy cloud_run --a2a` でも A2A サーバーモード。

## よくあるエラー

`ConnectionRefusedError`（サーバー未起動）/ `TimeoutError`（処理長すぎ → タイムアウト延長・Instruction 簡素化）/ `JSONDecodeError` / `KeyError: 'artifacts'`（完了前にアクセス）/ `422`（JSON 構造が仕様に不一致）/ `ImportError ClientEvent`（a2a-sdk 1.x 混入 → `pip install --force-reinstall "google-adk[a2a]==2.2.0" "a2a-sdk>=0.3.24,<0.4.0"`）。

ADK 側の挙動固定は `adk conformance record/test`（A2A 準拠テストではない）。A2A 公開面は `curl .../.well-known/agent-card.json | jq .` と Task ライフサイクルのスモークテストで確認。

## レビューポイント（ハンズオン 7.6.3）

Agent Card の skills が具体的か・examples あり・streaming 宣言・security_schemes／通信エラー（`A2AClientHTTPError` / `A2AClientTimeoutError`）と `TaskState.failed` の扱い、`input_required` 継続フロー／ビジネスロジックと A2A 公開部の分離／シークレット直書きなし／SSE 3 種の区別とクリーンアップ。
